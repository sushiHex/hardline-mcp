# swim-lanes

Same task, N lanes, run in parallel and blind to each other. You compare at the
finish and merge.

## Run it

1. Write one brief and send it to every lane unchanged; the lanes differ by
   model or effort. To red-team, make the shared brief adversarial ("break this").
   Several concerns (feasibility, security, cost) go into the one brief as
   numbered questions every lane answers, never one concern per lane.
2. Run one round with every lane (see "Running a round").
3. Merge:
   - findings more than one lane reached: still verify them; shared material
     produces shared mistakes;
   - findings only one lane reached: verify before adopting; a lone finding is
     often the valuable one;
   - lanes that contradict each other: settle it against source, or take it
     to a roundtable.
4. Report the merge.

## Proposals

When the task asks for competing proposals (a design, a name), not a review
(a review that suggests fixes is still a review), add a judging round: send
each proposal in full, unattributed, to a lane that did not write it (with two lanes, they swap; prefer a judge on a different model, since a
model may recognise its own prose). Pick one or merge the best parts; the
judges advise.
